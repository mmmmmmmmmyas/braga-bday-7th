# Braga Star Constellation Timeline

## Quick start (VS Code)
1. Unzip, open the folder in VS Code.
2. **Rename `CLAUDE.template.md` → `CLAUDE.md`** (Claude Code auto-loads it; it holds the locked design rules).
3. Run `npm run dev` → open http://localhost:5173 (or right-click `index.html` → "Open with Live Server"). It must be served over HTTP — double-clicking `index.html` won't load the JSON/audio.


## Project layout
- `index.html` — the intro page (plain HTML and JS), and the entry point.

- `support.js` — runtime that renders `timeline.html`. Keep it next to `timeline.html`.

## Overview
A full-screen, interactive company timeline (Braga Technologies, Day 0 → 2027) drawn as a star constellation. Each year is a node on a main line; projects and milestones are stars connected by constellation lines. The user travels horizontally section-by-section (one section = the span between two years) through a pseudo-3D camera with depth layers, tilts, and hovers stars to reveal pop-up chips, info cards and photos. Background music and hover SFX.

## About the Design Files
`timeline.html` is a **working HTML prototype** of the intended look and behaviour. You can keep iterating on it directly, or port it to a framework (e.g. Vite + React / vanilla TS) — if porting, match everything below exactly.

The prototype is a "Design Component" (`timeline.html`) rendered by a small proprietary runtime (`support.js`). Treat the template as JSX-like markup (`{{ x }}` = value from `renderVals()`, `<sc-for>` = map, `<sc-if>` = conditional) and the `class Component` as a React class component whose `renderVals()` is `render()`'s data. All of the real logic (camera math, hover cards, audio) is plain DOM/JS and ports directly.

**Editing tips:** inline styles only in the template; `{{ }}` holes are dotted lookups only (compute values in `renderVals()`); per-frame motion lives in `tick()` and writes to the DOM directly.

## Fidelity
**High-fidelity.** Final colours, type, spacing, motion and audio. Recreate pixel- and timing-accurately.

## Sign-in data (Supabase)

- `supabase/schema.sql`: tables `crew` (id, tag, name, team, title, emails[], year, photo) and `sign_ins`, both locked by row level security with no policies, plus the two functions the browser may call: `crew_names()` and `sign_in(p_id, p_email)`.
- Messages (testing phase): table `messages`, one row per crew member (80–240 characters, trimmed), locked by row level security like the others. `submit_message(p_tag, p_email, p_body)` checks the email like `sign_in()` and the length again, saves once and returns `saved`, `already` (sent before), `invalid` or `denied`. `sign_in()` also returns the person's own message (or null); the intro stores it in `sessionStorage['braga7.message']` (or clears it), so the message section shows its sent state on any device. `crew_profiles()` returns each person's message too, for the message stars.
- `supabase/reset-messages.sql` ends a testing round: it copies every message into `messages_test_archive` (with the reset time), then empties `messages`, so everyone can send again. Someone already on the site keeps their old sent state until they sign in again.
- `supabase/setup.private.sql` (git-ignored, never commit): the schema plus every staff row. Paste it into Supabase → SQL Editor → Run; it is safe to run again. Later changes to the staff list also get a small `supabase/update-<date>.private.sql` (also git-ignored) that touches only the rows that changed, so existing rows are left alone. The list has 72 people (crew numbers 001–072), including Bhumi Warih staff, whose work emails are on `bwgeohydromatics.com`, and six Magang Hub interns (067–072, "Internship", no photos yet).
- Crew photos live in Supabase Storage, in the public bucket `crew-photos` (WebP only, 1 MB max), never in the repo. The originals are in `assets/photos/` (`photo-<crew number>.png`, 200 × 200px) and the upload-ready copies in `assets/photos-supabase/` (WebP at quality 80, about 3 KB each, named `<crew number>-<random>.webp` so nobody can guess another person's link); `assets/` is git-ignored. Each person's `crew.photo` holds their file's public link, set by `supabase/photos-2026-11-10.private.sql` (also included at the end of `setup.private.sql`), and `sign_in()` returns it only to that person; `crew_profiles()` returns everyone's name, title and photo link, for the message stars, only to someone whose tag and work email match. People without a photo have a name card instead.
- The project URL and publishable key are at the top of the script in `index.html`. Never put the secret / service_role key in the site.
- The timeline crew card shows the signed-in profile: crew number, `EST. <year joined>`, their photo (filling the 102 × 102px tile, cover-cropped; the grey `#d9d9d9` tile stays for guests and anyone without a photo link), name, the email used, and title. The small crew card is a copy, so it shows the photo too. `timeline.html` redirects to the intro unless a profile is stored.

### World / data model (`constellation.json`)
World canvas 13996.6 × 1080. Fields:
- `years[]`: `{year, x, y, lx, base, pill?, image?, images?, info?}` — `x,y` dot centre; `lx` label left; `base` label baseline. 2026 has `pill:true`.
- `stars[]`: `{id, x, y, r, label, fs, lx, ly, kind:'project'|'milestone'|'event', style:'p'|'c'|'i', image?, images?, info?}`. `style` p = Archivo 500 0.04em; c = Oswald 600 0.04em; i = Archivo 700 italic −0.02em. Label `line-height = fs×1.35`, top = `ly − fs×1.08`, `white-space:pre` (labels may contain `\n`).
- `images`: array of path strings or `{src, scale}` (e.g. intan logo at `scale:0.3`).
- `info`: `{title, body: string[]}` → info card.
- `lines[]`: `{d, nodes}` — `d` is a filled outline SVG path in world coords (lines are drawn as filled shapes); `nodes` = keys (`s<id>` / `y<year>`) the line connects. A path with >30 `M` sub-paths is a **dashed** line: re-built as a stroked polyline through its nodes, stroke-width `max(1, 1.4·s)`, dasharray `9·s·1.4 12·s·1.4`.
- Sections: section 0 = x 0 → 1840, "Starting Point": 1440 of framed content (`START`) plus a 400 empty spacer (`SPACER`) before Day 0. Section 1 = 1840 → years[0].x ("Day 0 → 2019"), section i = years[i−2].x → years[i−1].x ("2019 → 2020"), the 2026 → 2027 section ends at W − 2880, followed by the 1440-wide message section "M" (`MSG`) and the 1440-wide final section "F" (`TAIL`). ## Interactions & Behavior
### Camera / travel
- Base scale `s = skyH·0.94 / 1080`. Each section has a depth z (`Z = [0,0,0,20,20,40,60,60,40,70,70,70]`); layer scale `k = max(0.2, 1 + z/100·depth)` with `depth = 2`. Layers are rendered with perspective `D = 3·max(vw, skyH)` and a per-frame `matrix3d` (see `tick()`); world points are projected with the same matrix for lines and pop-up anchors.
- Auto-framing: the focused section's bounding box (stars + labels + next year label) is fitted to `0.9·vw` wide and `skyH − 2·min(60, 0.18·skyH)` tall (zoom factor capped 2.2); blended smoothly between neighbouring sections with smoothstep, eased `1 − e^(−9·dt)`.
- **Wheel**: `targetX += (|dX|>|dY| ? dX : dY) · 0.8 / (s·fit)`. Camera follows `cam += (target − cam)·0.085` per frame. After 160ms without input, soft-snap target to the nearest section centre, only between section 01 and the 2026 section (`’25–26`). Between the centres of sections 00 and 01, and from the 2026 section onwards, there is no snapping: the camera rests where it is left, and section 00 keeps focus until the camera is 80% of the way to section 01.
- **Drag** (pointer, left button): axis locks after 6px movement. Horizontal: 1:1 × 0.8 follow; on release, momentum `target −= v·260·0.8/(s·fit)` (v = smoothed px/ms; zeroed if pointer was still for >100ms), then soft-snap. Vertical: pitch = `p0 − dy/30`, clamped ±10°.
- **Keys**: ← / → previous/next section. Esc closes zoom.
- **Orbit**: when the camera settles on a new section (280ms), pick a random tilt of 70–100% × 10° (`orbitTilt`) on either yaw or pitch (sign random); critically-damped spring ω = 3.2. Section depth z also springs.
- Changing focused section clears hover and retracts pop-ups immediately (unless a photo is zoomed).

### Hover
- Only nodes in the focused section (and its two bounding year dots / pill) accept pointer events.
- Entering a node: play hover SFX (not when re-entering the same node within 250ms), set hovered key, spawn pop-ups.
- **Placement**: for each pop-up, try up to 60 random angles θ; distance from star centre = `starScreenRadius + 14 + rand·28 + (w/2)|cosθ| + (h/2)|sinθ|` (chip: `+10 + rand·14`). Score = area inside viewport (12px margin) − full area − 2 × overlap with already placed pop-ups (+10px padding). Take the first fully-inside, non-overlapping candidate, else the best. Final position is also clamped inside the viewport each frame and follows the star as the camera moves.
- **Animation**: progress p in [0,1]; in 0.42s, out 0.24s; stagger −0.12 per item. Position = lerp(star centre → target, easeOutCubic(p)); scale = `0.08 + 0.92·easeOutBack(p)` (c1 = 1.5); opacity = `min(1, 3p)`. Pop-ups ignore the pointer until p > 0.85.
- **Persistence**: pop-ups stay while the cursor is over the star (radius `max(rs+8, 16)`) or any pop-up (geometric check every frame). After leaving both: **600ms** grace, then retract. Hovering a different node replaces them immediately.
- **Zoom**: click a photo card → card grows to `min(3/UI, (vh−80)/h, (vw−80)/w)` × its size, centred, from its current rect (FLIP, 0.45s `cubic-bezier(.2,.8,.2,1)`), padding 10px, radius 18px (image 12px), bg `#080504`, backdrop `rgba(8,5,4,.8)` fading 0.35s. Click anywhere (image or backdrop) or Esc → shrink back into the card (0.35s `cubic-bezier(.4,0,.2,1)`).

### Cursor ring (sky only, hidden when pointer leaves)
- 1px `rgba(244,243,239,.35)` circle centred on the cursor. Size eases (`1 − e^(−10dt)`) to 100px (no hover) / 200px (hovering a node). Pulse `±2.5%`, period 2.2s (3.6s while hovering).
- **Idle hint** after 400ms with no move/scroll/drag/key: blend factor fades in (rate 2.5/s, out 8/s). Ring pulse becomes 100% ↔ 60% of its base size (same period). Arched text via SVG `<textPath>`: "Drag, Scroll, Hover" on the top arc (radius base/2 + 7), "to Traverse The Timeline" on the bottom arc (radius base/2 + 15, drawn left→right so glyphs read upright). Archivo 10.67px (8pt), 0.08em, white; opacity 0.8 ↔ 0.6 (3s cosine loop). Text radius stays on the base (non-pulsing) size.

### Audio (Web Audio API)
- The timeline starts with sound on at the middle step, `low` (music at 0.12, hover SFX at 0.6); the volume icon cycles low → off → full. Context resumes on first `pointerdown`/`keydown` (browser autoplay policy). Suspended when tab hidden.
- **BGM** `space-music.mp3`: decode, trim leading/trailing samples below |0.002|, loop by scheduling overlapping buffer sources with an equal-power crossfade of `min(4s, len/4)` (sin/cos curves, 128 points). Master gain 0.385 (full) / 0.12 (low) / 0 (off), fades over 1.2s on toggle. Hover SFX gain is 0.6 in full and low, and 0.3 in off, so it stays audible when the music is off.
- **Hover SFX** `hover.mp3`, played at full level for stars and years and at half their audible loudness for the other interactive UI (voice level 0.5 when the SFX gain is 0.3 and 0.48 when it is 0.6, measured by an offline render of the chain): timeline cells, the volume button, the Open invitation button, zoomable photo and video cards, and on the intro the Accept invitation, Skip login, Back, Accept as (when active) and name list items. Text fields and inactive buttons are silent. It plays once per entry into an element. Gain 0.6 (0.3 when the music is off) → DynamicsCompressor (threshold −18, knee 12, ratio 6, attack 3ms, release 200ms). One voice at a time: previous voice fades to 0 in 60ms; new voice 8ms attack; ignore retriggers < 70ms; peak 0.55 if retriggered < 400ms after the last, else 1.

## State Management
- `soundMode: 'full'|'low'|'off'` (default `'low'`: music at 0.12, hover SFX at 0.6), `data` (loaded JSON), `vw/vh`, `centerSec` (focused section index), `hoverKey` (`s<id>` / `y<year>` / null).
- Per-frame (non-React) state: camera `camW/targetW`, `yaw/pitch` + velocities and targets, `zp`, `fitC/fitO/fitX`, drag object, cursor `mx/my`, `lastAct`, pop-up card list, zoom object, ray angles. Drive with one `requestAnimationFrame` loop writing transforms directly to DOM — don't push per-frame values through React state.
- Data: fetch `constellation.json` on mount; preload every image to learn natural dimensions before first hover.
